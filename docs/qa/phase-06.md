# Phase 6 — administrative follow-through

Date: 14 October 2026. Local sandbox functional gates passed. Synthetic patient, conversation input, windows and orders only; live providers and physical quality remain open.

## Implemented

- Separate owned HTTP office process, persisted stable appointment resources, availability revisions, required sandbox orders, unique request IDs and correlated confirmed/rejected receipts. Changing a scenario cannot resurrect a reserved slot.
- Explicit patient lookup scope; a selected window does not approve a booking. Separate clinician attestation/order and patient approval of the exact digest. No source/model text grants administrative authority.
- Patient-only office cues and shared closeout use source/check time and current result snapshots. Public speech still requires current participant consent and shared plan plus every source.
- Transactional action/outbox creation, worker leases and request idempotency. A durable dispatch decision precedes network I/O; network latency holds no encounter/media lock. Queued work loses to prior correction/revocation. Already dispatched work is reconciled honestly; confirmed reservations are never silently undone.
- Guest APIs require the current shared plan and source fingerprint. Stale action details cannot inherit a corrected plan's audience. Patient receipts remain available after corrections/withdrawal.
- Visibly sandbox office controls, patient/clinician/family panels, actual receipt IDs, missing-order and unknown-state messaging, mobile layout and persistent mutation errors.
